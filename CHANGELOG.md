# Changelog

Build log for HotSeat by **Ember Syndicate** (PromptWars × GDG On Campus, 26 Sep 2026).
Each entry is one logical change, ready to be committed with the message shown.

## 2026-09-26

### docs: design spec and implementation plan
- `docs/specs/2026-09-26-hotseat-design.md`: problem, solution, architecture, security, accessibility, judging fit.
- `docs/plans/2026-09-26-hotseat.md`: task-by-task build plan.

### chore: scaffold Vite + React + TypeScript app with tests, lint and CI
- Vite 8, React 19, TypeScript 6 (strict), Vitest 5 + Testing Library, ESLint 10 flat config.
- `.github/workflows/ci.yml` runs lint, typecheck, tests, build and the Python tests.
- Responsive, accessible base styles (`clamp()` type scale, `100dvh` layout, reduced-motion support, AA contrast).

### feat: anonymising company-profile distillation pipeline
- `scripts/distill_companies.py`: past candidates' feedback → PII redaction → Gemini structured summary → PII scrub → `src/data/companies.json`.
- `scripts/test_distill_companies.py`: 4 tests covering redaction of names, roll numbers, emails and phone numbers.

### feat: interview session state machine, scoring and local storage
- `src/domain/model.ts`: Zod schemas as the single source of truth for AI response shapes.
- `src/domain/session.ts`: pure reducer (extract → hot seat → results → re-defend) and defensibility score.
- `src/domain/storage.ts`: browser-only persistence with safe fallbacks. 14 tests.

### feat: Gemini client with structured output, prompt-injection guard and rate limiting
- `src/ai/jsonSchema.ts`: Zod → Gemini JSON Schema.
- `src/ai/prompts.ts`: system instruction, company lens, untrusted-text escaping.
- `src/ai/client.ts`: validated JSON responses with one retry; `src/lib/rateLimiter.ts`: 12 calls/min.

### feat: Firebase AI Logic adapter, config checks, PDF validation, company profiles
- `src/lib/firebase.ts`: Gemini via Firebase AI Logic (no API key in the browser), optional App Check and Analytics.
- `src/lib/pdf.ts`: type, size and `%PDF-` signature checks.
- `src/data/companies.ts`: schema-validated company profiles.

### feat: hot seat interview, resume heatmap and fix plan UI
- Start screen (upload, company, consent), hot seat (typed or spoken answers, finish now), results heatmap
  (icon + label + colour), fix plan and re-defend.
- Full-flow integration test with a fake AI client. 40 tests total.

### docs: README, Firebase Hosting config with security headers
- `README.md`: challenge-to-feature mapping, architecture, AI and prompting, Google services, security, accessibility, testing.
- `firebase.json`: SPA rewrite, CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, immutable asset caching.

### fix: layout overflow on narrow screens
- Grid columns could grow to the width of the longest company name, pushing the consent text off-screen.
  Columns are now capped at the container width (`minmax(0, 1fr)`); verified with no horizontal scroll at 375 px.

### fix: clearer AI error messages
- A Firebase project without AI Logic enabled now says so instead of showing a generic error.
- The rate-limit check no longer matches ordinary words such as "generate". 42 tests total.

### perf: fast model tier for interview turns
- Measured live: an interview turn on `gemini-3.8-flash` took 7–31 s on the free tier; `gemini-3.5-flash-lite`
  took 2.4–3.4 s with the same verdicts.
- Resume reading (once per session) stays on `gemini-3.8-flash`; assessments and fix plans use
  `gemini-3.5-flash-lite` (`VITE_GEMINI_FAST_MODEL`). 43 tests total.

### feat: quota fallback for resume reading
- If the quality model's free-tier daily quota is exhausted (seen live: `GenerateRequestsPerDayPerProjectPerModel-FreeTier`),
  resume reading retries on the fast tier instead of failing. 44 tests total.

### deploy: live on Firebase Hosting
- https://gdgxpromtwar.web.app, verified end to end (resume → first question in ~12 s), no console or CSP errors,
  all security headers served.

### data: company profiles distilled
- Anonymised interview profiles for 59 companies with the most interview reports (Oracle, TCS, ZOHO, Cognizant,
  Deloitte, Infosys, IBM, D. E. Shaw and more), generated by `scripts/distill_companies.py`.
- Verified: 0 email, phone or roll-number patterns and 0 name mentions in `src/data/companies.json`.
- Redeployed to https://gdgxpromtwar.web.app and verified live (Infosys lens, first question in 9 s).

### feat: company preparation guide
- New `PrepGuide` panel: rounds and format, areas to prepare, recommended resources, real questions asked,
  HR questions and tips. Shown when a company is chosen on the start screen and again under the results.
- Company data regenerated for 60 companies with a new `resources` field (sites, books, platforms), all verified
  free of personal data. 49 tests total.

### chore: neutral source wording
- The app, prompts, README and docs describe the data as anonymised placement interview reports from past
  candidates, with no institution named.
- Institution-specific redaction terms moved out of the code into the git-ignored `.env.local`
  (`REDACT_TERMS`); the data script strips them from input and output. 7 Python tests.
- Redeployed and verified live: 60 companies, guide renders, no institution words anywhere on the page,
  full AI flow working.

### feat: preparation guide tab
- Top-level tab bar ("Hot seat" | "Preparation guide", `aria-current` on the active tab). The guide tab lets anyone
  browse all 60 company guides without uploading a resume or calling the AI. 53 tests total.

### feat: clickable preparation resources
- Every recommended resource in a guide is now a link that opens in a new tab (`noopener noreferrer`, screen-reader
  note). URLs come from a curated table of official sites (`src/data/resourceLinks.ts`), never from the model:
  of the 78 distinct resources, 54 link to official sites, 8 to a YouTube search (teachers' channels) and
  16 to a Google search (mostly books). 58 tests total.

### fix: stale page after deploys
- Firebase served `index.html` with `max-age=3600`, so browsers kept showing the previous version for up to an hour.
  The page is now `no-cache` (hashed assets stay immutable), so every deploy shows up on the next load.
